# 알렉스(사내 AI) 연동 가이드 — 기존 파이프라인에 doortrim-atlas 붙이기

이 문서는 사내 AI(알렉스)가 그대로 읽고 작업할 수 있도록 쓴 기술 문서입니다. 사용자 안내는 README.md, 설치는 INSTALL_OFFLINE.md.

## 1. 역할 분담

| 기존 사내 모듈 | doortrim-atlas 가 대신/보강하는 것 | 그대로 쓰는 것 |
|---|---|---|
| ① 부품 자동분류 (SAM2/Region-Growing) | **전면 대체**: `segment` → 면(face)별 표준부품코드 | — |
| ② 치수·중량 예측 (형상유사도 zero-shot) | 입력이 스킨(A면)이라 **가시 면적 기준**의 같은 방식을 내장(`predict.py`). 기존 모듈을 쓰려면 `parts.csv` 의 면적·bbox 를 넘기면 됨 | 과거 부품의 실측 중량·재질은 DB 에서 manifest 로 전달 |
| ③ 원가·성능 | 재질 예측 + 단가표가 있으면 재료비 계산. 두께 기반 합부 규칙은 두께가 없으므로 **기존 규칙 모듈에 예측 재질/유사차종 두께를 넘겨 판정** | material_cost_reference, 규칙 판정 |
| 승인체계 (approve_classification) | 사람이 결과를 고친 신규 차종을 `build-atlas --append` 로 아틀라스에 추가 → 학습 데이터가 자동으로 늘어남 | classification_decisions |

## 2. 입력 스키마

### 2-1. manifest.csv (아틀라스 구축 입력)
필수 열: `atlas_id`(완제품 단위 = 차종+좌우, 예 `GL3_LH_12`), `stl_path`, `standard_part_code`
선택 열: `weight_g`, `material`, `vehicle`, `side`, `body_name`, `part_no`, `note`

`make-manifest` 는 `part_bodies.standard_part_code` 를 가진 테이블을 찾아 자동으로 SQL 을 추측합니다
(`inspect-db` 로 출력). 사내 스키마에 맞지 않으면 아래 틀로 SQL 을 써서 `--sql my.sql` 로 넘기세요. **열 별칭만 맞으면 됩니다.**

```sql
SELECT
  v.vehicle_name || '_' || p.side || '_' || p.id AS atlas_id,
  b.stl_path                                    AS stl_path,
  b.standard_part_code                          AS standard_part_code,
  m.weight_g                                    AS weight_g,       -- 실측 중량(없으면 NULL)
  m.material                                    AS material,       -- 재질 코드(없으면 NULL)
  v.vehicle_name AS vehicle, p.side AS side, b.body_name AS body_name, p.part_no AS part_no
FROM part_bodies b
LEFT JOIN part_measurements m ON m.body_id = b.id
LEFT JOIN parts p ON p.id = b.part_id
LEFT JOIN vehicles v ON v.id = p.vehicle_id
WHERE b.standard_part_code IS NOT NULL AND TRIM(b.standard_part_code) <> '';
```
* 2D BOM(assy_structure_items)의 중량이 더 정확하면 `linked_part_no` 로 조인해 `weight_g` 에 넣으세요.
* 같은 코드의 바디가 한 완제품에 여러 개면(클립 등) 코드별로 면적·중량이 합산됩니다.
* `stl_path` 가 상대경로면 `--stl-root` 로 루트를 지정.

### 2-2. 신규 스킨
STL 파일 1개 또는 STL 폴더(Geometrical Set 별 조각). OBJ/PLY 도 가능. 단위 mm.

## 3. 파이썬 API (CLI 대신 코드에서 호출)

```python
import sys; sys.path.insert(0, r"D:\도구\doortrim-atlas")
from doortrim_atlas.config import Config
from doortrim_atlas.atlas import Library, build_atlas, read_manifest
from doortrim_atlas.classifier import train_classifier, save_classifier, load_classifier
from doortrim_atlas.segment import segment_mesh_files
from doortrim_atlas.predict import run_prediction, load_cost_table
from doortrim_atlas.evaluate import evaluate_library

cfg = Config.load(None)                       # 또는 Config.load("my.json")

# (1) 아틀라스 구축 — 완제품 단위로 호출. 라이브러리는 중간 저장 가능
lib = Library(r"D:\도구\library")
for atlas_id, bodies in read_manifest("manifest.csv").items():
    build_atlas(atlas_id, bodies, lib, cfg, log=print)
lib.save()

# (2) 분류기
bundle = train_classifier(lib, cfg); save_classifier(bundle, r"D:\도구\library\classifier.pkl")

# (3) 평가 (dict 반환 + evaluation.csv / evaluation_summary.json 저장)
summary = evaluate_library(lib, cfg, r"D:\도구\library\evaluation", max_folds=10)

# (4) 신규 스킨
lib = Library.load(r"D:\도구\library"); bundle = load_classifier(r"D:\도구\library\classifier.pkl")
seg = segment_mesh_files(r"D:\신규\GL3_PE2_skin.stl", lib, bundle, cfg, r"D:\결과\GL3_PE2", log=print)
pred = run_prediction(seg, lib, cfg, r"D:\결과\GL3_PE2", cost_table=load_cost_table("단가표.csv"))
```

`seg["parts"][code]` 와 `pred["visible_parts"][code]` 가 핵심 결과입니다. (`seg["_meshes"]`, `seg["_face_labels"]`,
`seg["_result"]` 는 메쉬/면 라벨/점 단위 중간 결과이며 JSON 에는 저장되지 않습니다.)

점구름만 있을 때는 `segment.segment_points(P_mm, N_mm, lib, bundle, cfg)` 를 직접 호출합니다(evaluate 가 이 경로를 씁니다).

## 5. 기존 모듈과의 연결 포인트

* **중량(②)**: 기존 zero-shot 매칭을 그대로 쓰려면 입력 벡터를 `(area_visible_mm2, L_u, H_v, D_w)` 로 바꾸고, DB 쪽 비교값도
  아틀라스 JSON(`library/atlases/<id>.json` → `parts[code].area_visible_mm2`, `bbox_visible_mm`)을 쓰세요. 양쪽 정의가 같아야 합니다.
  스킨에는 부피(volume)가 없으므로 부피 축은 제외합니다.
* **원가(③)**: `material` → `material_cost_reference` 매칭. 복합재질 레이어 가중평균 로직은 기존 것을 그대로 호출.
* **성능 규칙(③)**: 규칙이 요구하는 두께는 `neighbors[0].atlas_id` 의 같은 코드 부품 두께(BOM Th:)를 기본값으로 넘기고,
  결과에 "두께는 유사차종 ○○ 참조" 라고 표기.
* **승인/되먹임**: 사람이 수정한 신규 차종의 부품별 STL(`parts/<코드>.stl`, 수정 후)을 manifest 에 추가 →
  `build-atlas --append --manifest new.csv --out library` → `train` 재실행. 이것으로 "기존 학습을 바탕으로" 가 누적됩니다.

## 6. 튜닝 요령 (증상 → 설정)

| 증상 | 설정(`--config`) |
|---|---|
| 작은 부품이 큰 부품에 먹힘 | `alpha_atlas: 0.4`, `cleanup_size_coef: 0.05`, `smooth_iters: 0` |
| 얼룩/노이즈 | `smooth_iters: 2~3`, `k_nn: 15` |
| 배치 편차 큼 | `nonrigid_search: 8~10`, `k_atlas: 12` |
| 첫 아틀라스 방향 오류 | `cabin_dir: "+y"/"-y"`, `up_dir`, `rear_dir` |
| 스킨 STL 에 뒷면(두께)이 있음 | 자동 판정(solid_like) 되지만 로그에서 확인; 필요 시 `vis_tol_mm` 조정 |
| 속도 | `raw_samples`, `atlas_points`, `skin_samples`, `skin_points`, `clf_trees` |

## 7. 코드별 IoU 가 낮을 때 원인 찾기

1. `library/previews/<id>.png` — 아틀라스 자체의 라벨/방향이 맞는지.
2. `library/evaluation/fold_<id>.png` — 예측 vs 정답 두 그림. 통째로 어긋나면 자세/정렬 문제(`scores` 의 1·2위 차이 확인),
   경계만 어긋나면 배치 편차(정상), 특정 코드만 빠지면 희귀 코드(상위 k 아틀라스에 없음) 또는 가려짐(`visible_fraction` 확인).
3. `evaluation.csv` 를 코드·차종별로 피벗해 "어느 차종이 평균을 깎는지" 확인 → 그 차종의 라벨 재검토(`approve_classification`).
